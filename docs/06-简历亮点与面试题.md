## 一、简历亮点（STAR 句式，可直接抄进简历）

1. **秒杀抢票一致性**：面对开票瞬间万级并发导致的**超卖与重复下单**风险，将"库存扣减 + 一人一单"封装进 **Redis Lua 脚本**原子执行，秒杀成功后经**本地消息表 + Kafka** 异步落单、消费者按唯一键幂等去重 → 库存**零超卖**、订单**零重单**，下单链路从 DB 直写降到 Redis 短路径【设计目标 P95<500ms】。

2. **通用领取引擎（抽象复用）**：发现"票的秒杀"与"券的领取"在**限量+限购+并发+幂等**上同构，抽出一个通用领取引擎（Lua 扣减 + 用户维度去重 + 幂等 + 异步落单），票与券复用同一套逻辑 → 消除两份一致性代码，降低各自出 bug 的风险。

3. **订单状态机与超时释放**：针对"未支付占坑"，设计五态订单状态机（待支付/已支付/已完成/已取消/已退款），通过**定时扫单 + 按 order_id 幂等**实现超时"三释放"（库存回补、座位释放、优惠券释放）→ 资源自动回收，杜绝占坑与重复释放。

4. **缓存三件套**：以**布隆过滤器 + 缓存空对象**防穿透，**逻辑过期 + 双重检查 + Redisson 分布式锁异步重建**防击穿，**随机 TTL** 防雪崩 → 热点查询命中提升、DB 压力显著下降。

5. **用户级限流**：基于 **Redis ZSet 滑动窗口 + Lua 原子脚本**（清理过期→计数→写入），配合自定义 **@RateLimit 注解 + AOP 切面**，对秒杀等接口做用户粒度无侵入限流 → 防恶意刷单与接口滥用。

6. **JWT 双 Token 认证**：Access Token 短有效期 + Refresh Token 长效，兼顾安全与体验；登出用黑名单即时失效。

7. **优惠券策略模式**：满减/折扣/立减用 `CouponStrategy` 策略模式承载，Spring 注入 `Map<type,strategy>` 路由 → 新增券种只加类、不改老代码（开闭原则）。

8. **选座并发一致性**：座位锁用 **Redis CAS + lock_token + TTL（短）**，与订单超时（长）分离，超时自动释放 → 并发下同一座位不会卖给两人。

9. **图片多规格压缩 + MinIO**：上传校验后等比压缩生成 原图/展示图/缩略图 三规格存 MinIO，列表走缩略图；大图异步压缩 → 降低存储占用与带宽。

## 二、高频面试题与话术（配 07 面试题库）

### 2.1 你项目最难的点是什么？怎么解决？
**答**：最难的是"**高并发下的一致性**"——既要零超卖，又要订单不重不漏，还要性能。我用"**Redis 裁决 + MQ 削峰 + 幂等兜底**"三段式：Redis Lua 原子扣减做裁决（防超卖）；Kafka 异步落单做削峰（保护 DB）；本地消息表保消息必达、消费者唯一键幂等防重单、超时扫单做对账（防丢单）。

### 2.2 为什么用 Kafka 不用 RabbitMQ？
**答**：见 `07-面试题库`。一句话——**大吞吐削峰 + 分区顺序 + 持久化**更适合抢票；RabbitMQ 适合复杂路由/低延迟/AMQP 场景。

### 2.3 怎么保证消息不丢、不重、不堆积？
**答**：不丢=本地消息表（业务+消息同库事务）+ 生产者 acks=all + 消费者手动提交；不重=消费者按订单唯一键幂等；不堆积=分区数预留并行度 + 消费端批量处理 + 死信兜底。

### 2.4 库存为什么放 Redis，怎么防超卖？
**答**：Redis 单线程 + Lua 把"校验库存→扣减→记用户已购"做成一次原子操作，天然无竞态、一次 RTT，避免 DB 被打爆。防超卖靠"原子扣减 + 库存>0 判断"在同一脚本内完成。

### 2.5 订单超时怎么办？
**答**：定时扫"待支付且超时"的订单 → 取消并按 order_id 幂等执行三释放（库存回补/座位释放/券释放）。

### 2.6 优惠券如何设计？（策略模式）
**答**：`CouponStrategy` 接口定义 `applicable` 与 `calculate`，满减/折扣/立减各一个实现，Spring 注入成 `Map<type,strategy>` 按券种路由；新增券种开闭原则。券与订单通过"锁定→使用/释放"联动，保证不重复使用。

### 2.7 票和券有什么相似？（亮点：抽象）
**答**：两者在"限量+限购+并发+幂等+状态机"上同构，我抽了通用领取引擎复用。

### 2.8 图片怎么处理？
**答**：MinIO 存储 + 多规格压缩 + 缩略图列表 + 异步压缩 + 孤儿清理。

### 2.9 数据库表怎么设计、索引怎么建？
**答**：见 `07-面试题库`（B+树/最左前缀/覆盖索引/回表/联合索引顺序）。

### 2.10 为什么用 MySQL？OpsMind 为什么用 PG？
**答**：见 `07-面试题库`（数据库选型对比）。
