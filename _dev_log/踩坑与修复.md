### [P-001] 2026-09-16 · 环境
- 现象：命令行 `java -version` 显示 **1.8.0_261**，而项目要求 JDK 21（Spring Boot 3 需 17+）。
- 原因：系统 PATH 里的 `java` 指向 Java 8；但 `JAVA_HOME=D:\JDK\jdk-21` 实际已装 JDK 21。
- 解决：构建时显式设置 `JAVA_HOME=D:\JDK\jdk-21` 再执行 `mvn`（Maven 走 JAVA_HOME 取 Java 21，验证 `mvn -version` = Java 21.0.4）。运行服务同理。
- 本机可用 JDK：`D:\JDK\jdk-21`（21.0.4）、`D:\JDK\jdk-17`、`C:\Users\86133\.jdks\openjdk-24`。
- 备注：其它工具（Docker 29.7.2、Maven 3.9.11）正常。

### [P-002] 2026-09-16 · 父工程（Maven Reactor）
- 现象：在父 `pom.xml` 的 `<modules>` 一次性取消注释启用 8 个模块后，`mvn install -DskipTests` 立即报 `Child module ...\ticketgo-seat\pom.xml ... does not exist`（共 7 个），构建根本没进入编译阶段。
- 原因：这 8 个模块目录虽已存在，但还没建各自的 `pom.xml`；Maven 读取聚合工程时会先校验所有 `<module>` 是否存在 pom，缺一个就整体读取失败。
- 解决：先为 8 个模块补齐最小 `pom.xml` 骨架（parent 指向 `ticketgo-parent` + `artifactId`），再执行构建，随后逐模块补代码。
- 收获/面试话术：Maven 多模块聚合是"先解析 reactor、后编译"，任一子模块缺 pom 会导致整个 reactor 加载失败——拆微服务时"先建骨架 pom 再填肉"比"先写代码"更稳。

### [P-003] 2026-09-16 · 各业务服务（common 组件扫描）
- 现象：`ticketgo-common` 里的 `GlobalExceptionHandler`（`@RestControllerAdvice`）不会自动生效——它在 `com.ticketgo.common` 包，而各服务的启动类只扫描自己 `com.ticketgo.<模块>` 包。
- 原因：`@SpringBootApplication` 默认只组件扫描启动类所在包及子包，common 不在扫描路径内，因此 `BizException` 不会被统一处理成 `Result`。
- 解决：每个服务启动类加 `@Import(GlobalExceptionHandler.class)` 显式注册该 Advice（比放宽 `@ComponentScan` 到 `com.ticketgo` 更精确、不误扫）。
- 收获/面试话术：公共模块里的"切面/Advice/拦截器"不会因为依赖传递而自动生效，必须显式注册或走自动装配（`spring.factories`/AutoConfiguration.imports），否则会出现"依赖引了、注解也在、就是不生效"的经典陷阱。

### [P-004] 2026-09-16 · 微服务跨库/降级
- 现象：多服务需要读同一批表（票档价格、座位、用户券），且 MinIO/Kafka 未启时不能阻塞主流程。
- 原因：本期单库单实例，跨服务强一致代价高；外部中间件非强依赖。
- 解决：① 只读/状态变更的跨域表（t_ticket_tier/t_seat/t_user_coupon）在各服务内用轻量 Mapper 直连同库读写，避免为简单查询引入 Feign；② 秒杀落单先写本地库 + 本地消息表，Kafka 投递失败由定时器重试并 `log.warn`；③ 图片优先走 MinIO，`putObject` 抛异常时降级写本地 `./uploads` 并通过 `/uploads/**` 暴露。④ 支付回调优先 `RestTemplate` 调 order 的 `mark-paid`，失败直接改库兜底。
- 收获/面试话术：最终一致链路（本地消息表）与外部依赖降级（存储/MQ/服务调用）要保证"主业务不因旁路组件不可用而失败"。

### [P-002] 2026-09-16 · 前端工程（ticketgo-frontend）
- 现象：`npm install` 之后输出 `npm warn allow-scripts 2 packages have install scripts not yet covered by allowScripts: vue-demi@0.14.10 (postinstall), esbuild@0.21.5 (postinstall: node install.js)`，担心 esbuild 二进制未安装导致 `npm run build` 失败。
- 原因：本机 npm 11 开启了 install 脚本白名单（安全策略），未执行的 postinstall 仅是校验；esbuild 的平台二进制实际由 `optionalDependencies`（`@esbuild/win32-x64`）在安装阶段落盘，无需 postinstall 也能运行。
- 解决：直接执行 `npm run build`，1711 个模块正常打包、17.11s 构建成功；`npm run preview` 返回 200。无需 `npm approve-scripts`。
- 收获/面试话术：npm 7+ 的 install 脚本安全策略与可选依赖（optionalDependencies）机制——构建工具靠平台二进制包分发，postinstall 只是兜底校验。

### [P-003] 2026-09-16 · 前端 · 统一响应体与 API 文档不一致
- 现象：`docs/05-API设计.md` 写响应格式为 `{success, data, error}`，但前端封装按 `code!==200` 判定会解析不到成功标志。
- 原因：实际后端 `ticketgo-common/.../result/Result.java` 定义为 `{code, message, data}`，成功码 `ResultCode.SUCCESS=200`。
- 解决：`src/api/request.js` 响应拦截以 `code === 200` 为成功并直接返回 `data`；`code===401` 清理本地凭证并跳登录；其余 `ElMessage.error(message)`；非统一响应体（数组/对象）原样返回，兼容 Mock。
- 收获：文档与代码冲突时以可运行的公共模块为准，并用「松耦合拦截器」兼容两种格式。

### [P-004] 2026-09-16 · 前端 · 后端未就绪导致白屏的风险
- 现象：网关 `localhost:8080` 未启动时，列表/详情接口报错会让页面空白。
- 解决：所有页面 `try/catch` 后降级——列表/详情/券/订单/座位均内置演示数据，并顶部显示 `el-alert`「后端服务暂未连接」；无数据时使用 `EmptyState` 空态。页面永不白屏。
- 收获：可演示性与健壮性兼顾——降级数据仅在请求失败/空结果时启用，联调时自动切回真实数据。

### [P-005] 2026-09-16 · 前端 · 倒计时以服务端时间为准
- 现象：秒杀/支付倒计时要准，但前端本地时钟可能偏差。
- 解决：`src/utils/time.js` 在启动时请求一次列表接口，读取响应头 `Date` 计算本地时钟偏移 `offset`，`CountdownTimer` 统一用 `serverNow()=Date.now()+offset` 计算剩余时间；后端不可用时偏移为 0（退化为本地时间）。
- 收获：无需额外的「服务端时间」接口即可校准，HTTP `Date` 响应头即可。

## 主会话联调记录（2026-09-16，P-006 起）

### [P-006] 2026-09-16 · Maven 父工程
- 现象：可执行 jar 启动报「没有主清单属性」。
- 原因：父工程用 `spring-boot-dependencies` BOM 导入，**未继承 spring-boot-starter-parent**，`spring-boot-maven-plugin` 的 `repackage` 默认执行未绑定。
- 解决：父 POM `pluginManagement` 中给该插件显式加 `<executions><execution><goals><goal>repackage</goal></goals></execution></executions>`。
- 话术：用 BOM 而非 starter-parent 时，需手动绑定 repackage，否则产物是普通 jar。

### [P-007] 2026-09-16 · 编译参数
- 现象：`@RequestParam` 无显式 name 时启动后报 `Name for argument ... not specified ... '-parameters' flag`，接口 400。
- 原因：未继承 starter-parent，`maven-compiler-plugin` 未自动开启 `-parameters`。
- 解决：父 POM 配 `maven-compiler-plugin` `<parameters>true</parameters>`；并必须 `mvn clean` 强制重编译才生效。
- 话术：Spring MVC 依赖参数名反射，未加 `-parameters` 时连 @RequestParam 都拿不到名字。

### [P-008] 2026-09-16 · 构建/Windows
- 现象：`mvn clean` 报 `Failed to delete ...ticketgo-gateway-1.0.0.jar`。
- 原因：**该服务进程仍在运行，Windows 锁住了 jar**。
- 解决：构建前先停掉在跑的服务进程（`Get-Process java | Stop-Process -Force`）。
- 话术：Windows 上 jar 被运行中 JVM 占用，clean 会失败。

### [P-009] 2026-09-16 · Docker
- 现象：`docker compose up` 拉镜像失败 `registry-1.docker.io ... timeout`。
- 原因：Docker Hub 网络不可达；本机已有 `docker.m.daocloud.io` 镜像源可用。
- 解决：`docker pull docker.m.daocloud.io/library/mysql:8.0` 后 `docker tag` 回标准名；Kafka/MinIO 镜像源受限，先跳过（后端对二者有降级）。
- 话术：国内环境用镜像加速器，pull 后再 tag 回官方名，compose 无需改。

### [P-010] 2026-09-16 · 端口冲突
- 现象：容器 MySQL 映射 3306 失败（本机已装 MySQL80 占用 3306）。
- 解决：容器映射改 `3307:3306`，各服务 datasource 端口同步改 3307。
- 话术：本机既有 MySQL 时，容器换端口而非停本机服务。

### [P-011] 2026-09-16 · 网关路由
- 现象：`/api/admin/**` 经网关 404。
- 原因：网关只配了 `/api/product/**` 等，没有 `/api/admin/**` 路由。
- 解决：网关补 `admin-product`(`/api/admin/product|session|tier`) 与 `admin-coupon` 路由。

### [P-012] 2026-09-16 · 订单服务分页
- 现象：`GET /api/order/list` 返回 `total=0`（订单其实已入库）。
- 原因：order 服务 **缺 MyBatis-Plus 分页插件** `PaginationInnerInterceptor`（product/cart/coupon 有，order 漏了）。
- 解决：order `BeanConfig` 补 `MybatisPlusInterceptor` + `PaginationInnerInterceptor(DbType.MYSQL)`。
- 话术：MP `selectPage` 不配分页插件时 total 恒为 0/不分页，是高频坑。

### [P-013] 2026-09-16 · 优惠券库存预热
- 现象：限量券上架后 `POST /api/coupon/receive/{id}` 返回 1003「未开票」。
- 原因：`publish` 未把券库存预热进 Redis，通用领取引擎返回 NOT_WARMED。
- 解决：`publish` 对限量券（stockType=0）按 totalQty 预热 `RedisKeys.couponStock(id)`。

### [P-014] 2026-09-16 · 支付闭环
- 现象：`pay` 返回 200 但订单仍「待支付」。
- 原因：`pay` 只写支付单，置订单已支付在 `callback` 里，前端一次调用不闭环。
- 解决：Mock `pay` 成功后直接 `markOrderPaid`（真实场景仍由支付渠道异步回调）。

### [P-015] 2026-09-16 · 镜像拉取（quay 镜像）
- 现象：`quay.io/strimzi/kafka`、`quay.io/minio/minio` 直连拉不动。
- 解决：用 docker.aityp.com 给出的国内源 `swr.cn-north-4.myhuaweicloud.com/ddn-k8s/quay.io/...` 拉取后 `docker tag` 回原名。
- 话术：aityp/渡渡鸟镜像站可把 quay.io 等镜像转国内源，pull 后 tag 回原仓库名，compose 无需感知。

### [P-016] 2026-09-16 · Kafka（Strimzi 独立 KRaft）
- 现象：Strimzi 镜像不是 bitnami 等价替换，不吃 `KAFKA_CFG_*`。
- 解决：用它自带的 `config/kraft/server.properties`（broker+controller 合并、advertised=localhost:9092、log.dirs=/tmp/kraft-combined-logs），command 里先 `kafka-storage.sh format` 再 `kafka-server-start.sh`；`user: root` 避免卷权限问题。默认 `auto.create.topics.enable=true`，topic 自动建。
- 话术：Strimzi 是给 Operator 用的镜像；独立跑要自己 format KRaft 存储 + 直接调 Kafka runner，不能套 bitnami 那套 env。

### [P-017] 2026-09-16 · Kafka 端到端验证
- 验证：秒杀 → 同库写 `t_message_outbox` → `OutboxDispatcher` 投递 `order-created` → outbox status 由 0 变 1 → order 消费者 offset=1、LAG=0（已消费）。
- 注意：早期 Kafka 未起时，outbox 重试 5 次后置 status=2(失败) 不再重投——生产应有"失败重投/告警"。

### [P-018] 2026-09-16 · 图片上传验证
- 现象1：PowerShell 5.1 的 `Invoke-RestMethod` 无 `-Form` 参数。
- 现象2：1×1 base64 PNG 被 Thumbnailator 报 `Error reading PNG metadata`。
- 解决：用 `curl.exe -F "file=@xxx"` 上传；测试图用 System.Drawing 生成正常的 200×200 PNG。

### [P-019] 2026-10-18 · 配置编码
- 现象：order 启动报 SnakeYAML `UnicodeReader` 解析异常；payment 同理。
- 原因：用 PowerShell `Set-Content` 追加 Seata 配置时，中文注释被写成非 UTF-8 字节，整份 yml 解析失败。
- 解决：用编辑器/Write 以 UTF-8 重写 yml，注释改英文，避免再次乱码。

### [P-020] 2026-10-18 · Docker Desktop
- 现象：`docker ps` 返回 500 `check if the server supports the requested API version`，容器全部 Exited(255)。
- 原因：Docker Desktop/WSL2 引擎异常（内存压力下更容易发生）。
- 解决：停 Docker Desktop → `wsl --shutdown` → 重新启动 Docker Desktop，等 `docker info` 成功后再起容器。

### [P-021] 2026-10-18 · 宿主机内存
- 现象：JVM 启动/运行报 `OutOfMemoryError: Metaspace` / `insufficient memory ... malloc failed`；coupon 启动成功后被杀。
- 原因：宿主可用内存仅 0.4~3GB，10 个 Spring Boot JVM + 6 个容器同时跑不下。
- 解决：`-Xms32m -Xmx128m -XX:MaxMetaspaceSize=96/160m -Xss256k -XX:+UseSerialGC`；**分批启动**；必要时停掉暂不用的服务/容器。演示核心链路只需 user/product/seckill/order/payment/gateway。

### [P-022] 2026-10-18 · Nacos
- 现象：服务启动报 `Connection refused: /127.0.0.1:9848`。
- 原因：Docker 引擎重启后容器未运行，Nacos gRPC 9848 不可达。
- 解决：先确认 `mysql/redis/nacos` 容器 Up 且 9848 可连，再启动业务服务。
- 注意：Windows WSL `networkingMode=mirrored` 下 `Get-NetTCPConnection -State Listen` 可能检测不到映射端口，需用 TcpClient 实测。

### [P-023] 2026-10-18 · 端口残留
- 现象：payment 重启报 `Port 8088 was already in use`。
- 原因：上一个 OOM 的进程仍持有端口。
- 解决：`netstat -ano | findstr :8088` 找 PID 后 `Stop-Process -Id <PID> -Force`，再启动。

### [OPS-001] 2026-10-18 · 关闭 deepseek harness 自启
- 定位：WSL Ubuntu 内 systemd 服务 `dsh-web.service`（enabled，随虚拟机自启）；安装目录 `D:\MyDownlod\deepseek-harness`，命令 `dsh`，配置 `~/.dsh`。
- 处理：`sudo systemctl stop dsh-web.service` + `sudo systemctl disable dsh-web.service`；验证 `is-enabled=disabled`、`is-active=inactive`。

### [P-024] 2026-10-18 · 验证码显示不全
- 现象：登录/注册页图形验证码只显示 3 个字符。
- 原因：后端生成 120×40，前端 `.captcha-box` 为 112×48 且 `img { object-fit: cover }`，按比例覆盖再左右裁剪，第 4 位被裁掉。
- 解决：后端改 `createLineCaptcha(160, 48, 4, 24)`；前端 `.captcha-box { width:160px; height:48px }` + `img { object-fit: contain }`。实测 PNG=160x48。

### [P-025] 2026-10-18 · Kafka 消费者反序列化
- 现象：`ConvertException: Can not Converter from [JSONObject] to [OrderCreatedMessage]`。
- 原因：Hutool `JSONUtil.toBean(String, record)` 不支持 Java record 的构造绑定。
- 解决：消费者改用 Spring 自带 Jackson `ObjectMapper.readValue(...)`；并把 `throw e` 改为 `throw new RuntimeException(e)`（Jackson 抛受检异常 `JsonProcessingException`，方法未声明 throws）。修复后日志仅有"收到落单消息"，无转换错误。
